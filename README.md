# Folio 書頁記憶

給 SillyTavern 的自動記憶擴充：**正文是書頁，小摘要是目錄。先查目錄，再取回原文。**

不用另一個後端插件、不用 Ollama、不用開額外視窗，也不用手動下載向量模型。

## 安裝

在酒館的 **擴充功能 → 安裝擴充功能** 貼上：

```text
https://github.com/ab003317/sillytavern-folio
```

安裝後重新整理酒館。擴充設定中會出現「書頁」，預設自動啟用。沿用酒館目前的「聊天補全」連線，不另外填金鑰。更新、停用、卸載也都使用酒館原本的擴充管理。

安裝包含約 24 MB 的中文模型及約 11 MB 的推理程式；它們是普通 Git 檔案，不是 LFS 指標。瀏覽器首次使用會從**你的酒館伺服器**載入這些檔案，不會連 CDN 或 Hugging Face。

如果你已有 Anima 或其他會整理／刪減歷史的插件，請先在酒館擴充管理停用其記憶功能，避免兩套系統同時改提示詞。Folio 不會刪除或遷移它们的資料，也不會解除其他插件已經設定的隱藏訊息。

## 平常怎麼用

直接聊天即可。「書頁」會顯示整理進度和異常，不需要設定樓層門檻、向量維度、top-k、插入深度或 token 配額，也沒有進階設定頁。

按「查閱記憶」可以：

- 搜尋人物、地點或事件，展開小摘要和原始正文。
- 查看「本次取用」，知道上次帶入哪些正文及選取原因。
- 釘選重要書頁，或只重新整理某一則，不必重跑整段聊天。
- 點 ⓘ 閱讀說明。手機與鍵盤也能操作，不需要滑鼠懸停。

## 如何記住故事

1. **逐則清理正文。** 玩家和角色的訊息都算一則；移除已知思考、摘要、狀態標籤、程式及樣式區塊，保留故事對話。未知格式不會猜測整塊刪除。
2. **逐段寫小摘要。** 長訊息按內容長度拆段，段段保存。不是「每 30 樓再總結一次」。記錄人名、地點、因果、關係與約定；沒有將原聊天改成摘要。
3. **建立本機索引。** 內建 BGE-small-zh-v1.5 int8，512 維；摘要再切小塊，避免長摘要混合太多情節。向量快取與聊天檔分開。
4. **發送前查目錄。** 以當前輸入做語意向量與 BM25 文字混合檢索，再讓額外的短模型請求讀候選摘要、選出正文；可以不選任何往事。
5. **把選中的原文放回歷史。** 透過酒館標準 `generate_interceptor` 調整這次的 `coreChat`，按原本時間順序保留選中正文與近期對話，讓它進入預設的 **Chat History／聊天歷史** 區塊。不是把全部摘要塞進系統提示或世界書。

容量取自酒館傳入的可用 prompt tokens（已扣回覆預留），歷史預算約占 45%、最多 14k；近期正文與召回共享上限。最新玩家回應和接續生成所需的當前回合優先保留，完整段落裝不下就不塞，不會截斷成假原文。其餘空間留給預設、角色卡、世界書等；最後仍由酒館原生的提示詞組裝器按剩餘容量裁剪。這不是對每個模型真實服務端限制的自動探測。

## 模型和費用

**向量是真的內建、本機運算。** 關閉頁面會終止 worker；閒置兩分鐘會釋放模型。不啟動服務、不佔新端口、不使用顯示卡或 Ollama API。模型以中文為主，沒有宣稱英文與所有語言的召回品質相同。

**摘要和選頁不是內建大語言模型。** 它們使用酒館現有供應商連線的獨立短請求，不帶整個角色預設。若該連線已列出適合的小模型，會優先選擇；沒有就沿用當前模型。具有供應商前綴的模型只在相同前綴中選擇，不猜不存在的模型 ID，也不改你聊天的全域模型。

這些額外請求可能產生該連線的費用。整理一則通常一個摘要請求；長正文每段一次；需要回憶時通常一個選頁請求。「查閱記憶」下方會顯示最近實際使用的模型。暫停自動記憶會停止新任務；你按「重新整理這一則」會要求重新生成該則摘要。

## 可靠性與資料

- 以正文、角色與清理版本的 **SHA-256** 核對，不用全域「最後處理到第幾樓」游標。改文、換 swipe、刪訊息後，舊摘要不會被當成新正文的摘要。
- 每段摘要都有本機完成記錄；重新整理頁面可續做。相同瀏覽器的多視窗透過 IndexedDB 交易鎖避免重複摘要。**不同瀏覽器／裝置不是同一把鎖**，不保證兩台同時編輯同一聊天時的衝突合併。
- 摘要保存在訊息 `extra.folio_memory`，隨酒館儲存聊天；本機 IndexedDB 保存完成記錄與可重建的向量。正文不複製進摘要欄，不把向量寫進聊天檔。
- 切換聊天、開始生成或取消時，取消舊的背景任務。摘要請求有 45 秒時限，選頁請求 16 秒，向量工作 60 秒；錯誤會退避重試，不無限併發。
- 向量失敗可用文字檢索；選頁模型失敗可用匹配備援，介面會說明。尚未整理的正文用暫時摘錄參與文字查詢，不假裝已完成摘要。
- 原始聊天不刪、不改文、不永久隱藏。停用後回到酒館原本的歷史處理；已保存的摘要留在聊天，避免卸載誤刪資料。
- 沒有遙測。正文／候選摘要只發往你現有的酒館模型連線；模型資源完全同源、本機向量化。程式不讀取伺服器上的 API 金鑰檔。

## 支援範圍

這是 **0.1.0**。已在 SillyTavern **1.18.0** 的原生載入、模型參數介面及攔截器上做隔離整合測試；目前摘要支援 **聊天補全** 連線。文字補全、工具／多媒體混合歷史會保留酒館原本處理，不冒險破壞協定。

普通局域網 HTTP 也能使用向量，不要求 HTTPS、WebGPU 或 SharedArrayBuffer。需支援 WebAssembly SIMD、Worker、IndexedDB 的現代瀏覽器。只有酒館頁面開著才會自動整理，不是伺服器離線排程。

`本次取用` 顯示的是本插件交給酒館的歷史；後續其他插件或酒館預算仍可能改動最終請求。預設必須保留 Chat History 區塊。檢索與模型摘要不可能保證每個細節永遠命中；重要設定仍應放在角色卡／世界書，釘選也仍受容量限制。

## 開發與測試

安裝使用不需要 Node/npm/Python。以下只是開發測試：

```sh
npm test
npm run check
python -m pip install playwright
python -m playwright install chromium
python tests/browser.py
```

`tests/browser.py` 在虛擬路由中運行真實的內建 ONNX 模型，付費模型使用合成回覆；檢查桌面／手機 UI、刷新去重、搜尋、原文召回和零外部資源請求，結束後關閉瀏覽器，不啟動本地測試伺服器。

`tests/host_readonly.py` 可對既有酒館做唯讀演練：設 `FOLIO_ST_URL` 後執行。它只在隔離瀏覽器裡插入擴充清單，攔截所有應用寫入與真實模型生成，使用合成正文檢查酒館實際介面，不安裝到伺服器。

測試邊界及記錄見 [TESTING.md](TESTING.md)。模型來源、雜湊與授權见 [THIRD_PARTY.md](THIRD_PARTY.md)。
